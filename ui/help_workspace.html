Getting Started

Purpose Of This Tool

The dashboard is a reporting tool only. It scans selected folders or drives and shows which folders, file types, and individual files are using the most storage.

It does not delete, move, rename, compress, kill, quarantine, upload, or modify files or processes. Cleanup decisions must be reviewed and performed manually by the user.

Recommended First Scan

For most users, start with C:\Users. This is usually faster and safer than scanning the full drive.

  • C:\Users\YourName\Downloads
  • C:\Users\YourName\Desktop
  • C:\Users\YourName\Documents
  • C:\Users\YourName\Videos
  • C:\Users\YourName\Pictures
How To Use The Dashboard
  1. Choose a drive or enter a folder path in the Scan tab.
  2. Read the safety notice and acknowledge it for full-drive or sensitive-folder scans.
  3. Start the scan and watch the Scan Status panel.
  4. Review Results: biggest folders, file types, biggest files, tree view, and skipped paths.
  5. Use Process Review for local process indicators, not final malware decisions.
  6. Open History to compare previous scans.
  7. Use Exit App when no scan is running to stop the local server.
Common Use Cases
  • Find large files in Downloads, Desktop, Videos, Pictures, and Documents.
  • Review old installers, ZIP files, archives, exports, videos, and backups.
  • Check large Unity, Blender, Unreal, programming, AI, or creative project folders.
  • Understand skipped or access-denied paths before rerunning as Administrator.
  • Review unfamiliar processes with local indicators and technical details.
  • Run another scan after cleanup to confirm reclaimed space.

Disk Scanning

Scan Settings Explained

These settings control how much detail the dashboard collects and displays. Higher values can show more detail, but they can also make scans and browser rendering slower.

  • Top items: the maximum number of biggest folders, file types, and files shown in the results tables. Example: use 100 for a quick cleanup review, or 300 when investigating a large project folder.
  • Tree depth: how many folder levels the Large Folder Tree expands. Example: 3 shows a simple overview like Users, Downloads, and Videos; 8 is useful for deep project folders.
  • Children per folder: the maximum number of subfolders shown under each folder in the tree. Example: 30 keeps the tree compact; 100 helps when a folder contains many important subfolders.
  • Min tree size MB: hides folders smaller than this size from the tree. Example: 100 focuses on large storage users, 500 makes full-drive scans easier to read, and 0 shows very small folders too.
Scan Setting Examples And Use Cases
  • Quick personal cleanup: scan C:\Users with top items 100, tree depth 3, children per folder 30, and min tree size 100 MB.
  • Full C drive review: keep the default settings or raise min tree size to 500 MB so Windows, app, and user folders are easier to compare. Leave reparse points unchecked unless you have a technical reason.
  • Deep project investigation: scan the specific project folder, then use top items 300, tree depth 8, children per folder 100, and min tree size 0 or 25 MB.
  • After cleanup: rerun the same folder scan with the same settings so the new history record can be compared with the previous result.
Reparse Points, Junctions, And Symlinks

Windows can create folder entries that point somewhere else instead of storing files directly inside that folder. These are commonly called reparse points, junctions, or symlinks.

  • Reparse point: the general Windows feature for special filesystem links and redirects.
  • Junction: a Windows directory link that redirects one folder path to another folder path. Example: a compatibility folder may point from one system location to another.
  • Symlink: a symbolic link created by a user, app, developer tool, backup tool, or package manager. Example: a project folder may link to shared assets on D:\SharedAssets.

The dashboard skips these by default to avoid scanning the same files twice, following loops, or showing misleading totals. Include them only when a technical user intentionally wants to follow linked folders and understands that totals may include redirected data.

Understanding Results

What To Review First
  • Downloads: old installers, duplicate ZIP files, downloaded videos, Unity packages, Blender files, and backup archives.
  • Desktop: temporary screenshots, copied project folders, exported builds, and old archives.
  • Videos: OBS recordings, gameplay captures, raw footage, and test exports.
  • Pictures: duplicate screenshots, old references, PNG exports, PSD files, and AI-generated images.
  • Project folders: generated build folders, caches, dependency folders, and old exports.
Good Cleanup Candidates
  • Old installers in Downloads after the app is already installed.
  • Duplicate ZIP, RAR, and 7Z files.
  • Old exported videos, game recordings, and render tests.
  • Temporary screenshots and failed downloads.
  • Old build folders and old exported Unity builds.
  • Old compressed backups after confirming another backup exists.
Recommended Cleanup Workflow
  1. Scan C:\Users first.
  2. Review the biggest folders manually and ask: Do I still need this? Is it active? Is it a backup? Can it be recreated? Is there an official cleanup method?
  3. Review file types such as .mp4, .zip, .unitypackage, .blend, and .log to understand storage patterns.
  4. Review biggest files one by one. Do not delete a large file unless you know what it is.
  5. Use safe cleanup methods first: Storage Sense, Disk Cleanup, uninstall unused apps, clear browser cache, clear launcher/editor cache, or move personal files to another drive.
  6. Run the scan again after cleanup to confirm the result.
Unity Project Notes

Common large folders include Library, Temp, Obj, Logs, Build, Builds, and UserSettings.

Do not casually delete Assets, ProjectSettings, or Packages. Library can often be regenerated, but close Unity first and understand that the next open may be slower.

Blender And 3D Notes

Large files may include .blend, .fbx, .obj, .glb, .gltf, .png, .tga, .exr, .psd, .wav, and .mp4.

Remove duplicate exports, old render tests, and archived versions only after confirming models, textures, and references are no longer needed.

Developer Folder Notes

Generated folders can be large: node_modules, .venv, venv, __pycache__, dist, build, .cache, .gradle, .nuget, obj, and bin.

Some can be regenerated, but do not delete source folders such as src, Assets, Scripts, ProjectSettings, Packages, or .git unless you know exactly what you are doing.

Process Verification

Process Review Caution

A process may look unfamiliar but still be legitimate. The dashboard shows local indicators such as path, publisher/signature data, memory use, and command line where available.

These indicators are not a final malware or safety verdict.

Security Check

Evidence, coverage and review priorities

Security Check is read-only. Standard and Advanced checks inspect their declared scopes only; unavailable or access-denied sources are not clean results. Review Coverage separately from the number of findings.

Review priorities are not malware verdicts. Baseline differences do not automatically prove compromise. Allowlisting reduces review priority but does not establish safety or remove evidence from reports.

Cancelled and failed checks can retain partial evidence. Not run, not recorded, unavailable and zero findings are different states. Keep reports and technical evidence private.

Installer Cache

Package review and backup-review manifests

The read-only Installer Cache review reports classifications, applicability, confidence and source coverage. A probable orphan or backup review candidate is not permission to delete a package.

Review incomplete checks and missing registered files. Manifest export revalidates scan-bound evidence, file snapshots and SHA-256 hashes. Keep exports private; no cache files are moved, repaired or deleted by this dashboard.

Safety and Troubleshooting

Important Do Rules
  • Do scan C:\Users or your own user folder first for a practical cleanup review.
  • Do open large folders manually before deleting anything.
  • Do use official cleanup tools first: Storage Sense, Disk Cleanup, app uninstallers, launcher cleanup tools, browser settings, and package manager cleanup commands.
  • Do run as Administrator only when you need a more complete full-drive scan.
  • Do keep reports private because they may include usernames, project names, client names, source code paths, and personal filenames.
  • Do close heavy apps such as Unity, Blender, Unreal, Visual Studio, game launchers, video editors, AI scripts, and backup tools when practical.
Important Don't Rules
  • Don't delete system files just because they are large.
  • Don't manually delete files inside C:\Windows, especially System32, WinSxS, Installer, or SoftwareDistribution.
  • Don't manually delete folders inside Program Files or Program Files (x86); use uninstallers instead.
  • Don't randomly delete AppData; it can contain browser profiles, game saves, app settings, local databases, sessions, and caches.
  • Don't randomly delete Unity Assets, ProjectSettings, or Packages.
  • Don't assume unknown folders or processes are harmful. NVIDIA, Microsoft, Unity, Visual Studio, package manager, and launcher folders can look unfamiliar but be legitimate.
  • Don't share reports publicly without redacting private paths.
Folders That Need Extra Care
  • C:\Windows
  • C:\Program Files and C:\Program Files (x86)
  • C:\ProgramData
  • C:\Users\YourName\AppData
  • C:\Recovery and C:\System Volume Information
  • Source code repositories, client project folders, database folders, AI datasets, and active game projects.
Report Privacy Reminder

Reports may reveal usernames, private projects, client names, file names, downloaded content, personal folder structure, business documents, and source code paths.

Before sharing, redact paths such as C:\Users\YourName\Documents\ClientName_PrivateProject.

Final Safety Rule

A large file is not automatically a bad file. Before deleting anything, confirm what it is, which app or project uses it, whether it can be recreated, whether you have a backup, whether there is an official cleanup method, and whether deleting it could break Windows, an app, or a project.

When unsure, do not delete it immediately. Back it up or move it to a temporary review folder first.
