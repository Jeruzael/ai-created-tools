# v1.29 Manual Browser Check

Date: 2026-10-31. Status: **NOT VERIFIED** until a human records actual results.
This is a procedure, not evidence of completed visual testing. Do not bypass a
browser, Windows, automation or approval restriction to perform it.

## Preparation

1. Use a non-Administrator terminal in the application repository. Keep existing
   records untouched by starting the disposable-storage harness:

   ```powershell
   python -u tests/native_smoke.py --serve --port 0
   ```

2. Note the printed disposable scan-fixture directory and actual local URL.
   Open that URL manually in your normal browser. Do not reuse an old port or
   another app's tab. If any permission/security barrier prevents access, stop
   and record **NOT VERIFIED** with its message. Do not change security settings.
3. Use only the printed fixture folder for scans. It contains generated files,
   not system data, junctions or symlinks. Keep screenshots and downloaded
   evidence private; do not publish paths, session tokens or machine inventories.

## Check Procedure

Record PASS, FAIL or NOT VERIFIED for each row, with browser/version, date,
ordinary-user context, steps, expected/actual behavior and private evidence path.
Do not mark a backend or Node test as a visual-browser pass.

| Check | Human Action and Expected Result |
| --- | --- |
| Startup/version | Confirm 1.29.0, readable layout, no overlapping controls or startup error. Navigate Scan, Results, Processes, Installer Cache, Security Check, History, Manual and About. Do not trigger system collection merely to change tabs. |
| Default disk scan | Choose the printed fixture folder, leave "Include reparse points, junctions, and symlinks" unchecked, acknowledge review and start. Results and History should load. Confirm the submitted `includeReparse` is Boolean `false` if browser developer tools are available. |
| Explicit reparse choice | On the same fixture, check the option, run, then uncheck and rerun. Requests/settings should retain Boolean `true`, then `false`. Because the fixture has no reparse points, this verifies the control and payload, not traversal of a real junction. |
| Tree stability | Expand Results' folder tree and change available tree controls. Completed-job polling should not reset expansion or selected controls. |
| Error/recovery | Enter a nonexistent child of the fixture folder. A clear error should appear without a running job; then scan the valid fixture successfully. |
| Scan cancellation | If a controlled scan remains active long enough, cancel it and confirm terminal cancelled state and partial results. If it finishes before cancellation can be exercised, mark this visual check NOT VERIFIED; do not substitute a full-drive scan. Backend event-gated cancellation has separate automated coverage. |
| Security controls | Confirm registry backup is disabled. Standard mode must not enable Advanced collection. Inspect Advanced mode and toggle WMI/Event Log/Sysmon controls, then return to Standard before running anything. Changing selection alone is not native Advanced verification. |
| Standard Security Check | Only on an approved host for read-only current-user collection, acknowledge and run Standard. Confirm progress, findings/details, coverage warnings and report downloads. Disabled, denied, unavailable and partial sources must not appear as complete inspection. |
| Security cancellation | When a Standard Check is still active, cancel and confirm cancellation, retained evidence and usable controls afterward. If timing prevents the attempt, record NOT VERIFIED. |
| Optional payload inspection | If developer tools are already permitted, inspect request JSON: Security options must be real Booleans, not quoted strings or numbers. Do not export or share request headers containing the session token. No developer-tools policy should be bypassed. |
| Installer review | On an approved host, run only read-only Installer review. Permission gaps should be visible; ineligible manifest export stays disabled. Do not apply packages, delete, move or quarantine anything. A no-candidate result does not verify an eligible real-cache export/hash. |
| Local allowlist | In this disposable session, use a reviewed Standard finding to add/export/import/remove a priority hint. Confirm the counts and reload behavior; these hints must not claim the item is safe or change Windows. Keep exports private. |
| Exit guard | While work is active, Exit App must be blocked. After completion, Exit App should stop this harness server. If another HTTP request is briefly in flight, an explicit busy response is permitted; retry after it finishes. Confirm the terminal returns and another request cannot reach the stopped server. |

If the harness remains open because a check failed, use its normal Exit App
control when idle. Do not terminate an active write or delete its temporary
directory manually. Record an unclean exit or blocked cleanup instead of
claiming successful persistence/cleanup. Do not close unrelated browser tabs.

## Separate Approvals and Evidence

Administrator behavior, native Advanced Review, successful Authenticode
verification and eligible real-cache manifest hashing remain **NOT VERIFIED**
unless separately exercised and recorded in an approved controlled environment.
This procedure does not authorize elevation, policy overrides, system changes,
merge or deployment. Do not treat inspecting Advanced controls, a mocked test,
or an unavailable signature provider as successful native verification.

Before merging, attach the human results to PR #1 or keep a reviewed private
record referenced there. Redact sensitive screenshots locally before sharing;
if screenshot capture is restricted, record the limitation and do not bypass it.
