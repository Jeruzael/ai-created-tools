# v1.29 Security and Reliability Audit

Date: 2026-10-31. This is an internal engineering audit and implementation
plan, not an external security assessment. Recorded before implementation.

## Baseline and Scope

- Application repository: `Jeruzael/ai-created-tools`, checked out in `windows/`.
- Baseline: `cdf3fb88abeeb4e69fb1b90bbb07acb6b9f18b33` (v1.28.0).
- Initial application working tree: clean; baseline suite: 28 passed, 0 failed,
  0 skipped (`python -m unittest discover -s windows/tests -v` from the parent).
- Development branch: `codex/v1-29-security-hardening`; target: `master`.
- The parent folder is a separate, uncommitted Git repository. Its layout will

  maintained READMEs and relevant requirements/roadmap documents.

All reproductions used mocks, temporary fixtures or in-memory storage. No system

## Established Findings

| Area | Evidence at baseline | Required correction |
| --- | --- | --- |
| HTTP requests | A fixture server accepted a `text/plain` action POST with a foreign Host and Origin; the action handler ran. An allowlist fixture was also changed through this request pattern. | Validate exact loopback Host plus bound port, browser Origin, session CSRF token, media type, body length and JSON shape before dispatch. |
| Record paths | Absolute and traversal-like record IDs constructed paths outside the intended directory; a controlled external JSON fixture was readable. | Strict generated-ID format and resolved directory containment. |
| Job admission | Barrier-controlled scan/scan, security/security and mixed starts each admitted both requests. | Atomic final admission and registration under one operation lock. |
| Worker ownership | Event-controlled older workers overwrote newer registrations; cancellation could signal only the newer worker while an older completion hid it. | Identity-guarded progress, completion and operation release. |
| Shutdown and Installer work | New jobs started after shutdown; shutdown succeeded during blocked Installer review/revalidation; reviews could publish in reverse order. | Shared operation ownership, closed admission after shutdown, guaranteed release. |
| Worker failures | Injected thread-launch/result-construction errors left phantom running state; late cancellation could publish completed. | Launch rollback, terminal cleanup and an explicit cancellation/completion boundary. |
| Persistence | Injected direct-write failures truncated valid JSON. Interleaved imports lost an entry; import could undo a removal. | Same-directory temporary write, flush/fsync, atomic replacement, full serialized read-modify-write transactions. |
| Allowlist integrity | Malformed existing data became an empty allowlist and was overwritten. A 5,001-entry merged document was saved, then loaded as empty. String `"false"` became active. | Explicit recovery errors, strict supported schema/Boolean validation, complete merged-document validation, preservation of original data on failure. |
| Related records | Security records were written twice with inconsistent failure state; valid JSON arrays crashed history; unsupported baselines could compare as empty. | One validated atomic record publication, validated related structures and coherent failure status. |
| Collector evidence | Registry errors 5 and 1018 looked like normal end-of-enumeration 259. A zero-exit PowerShell result with access-denied stderr could become a clean-looking finding. | Preserve source errors and distinguish absent, denied, partial and failed evidence. |
| Coverage and cancellation | `collectors_connected` was always true, including not-run/failed/cancelled cases. All failed standard collectors could still look complete; cancellation discarded accumulated phase findings. | Canonical per-collector coverage ledger, incremental evidence retention, honest terminal state. |
| Verification and presentation | Unavailable signatures were labelled verified; a 500-candidate cap was silent; advanced references were collected after verification. UI/report variants omitted relevant coverage detail. | Explicit verification limits/gaps, collect before verifying, consistent API/history/UI/export projections. |

The HTTP result establishes missing server protections, **not a demonstrated
end-to-end browser exploit**. Same-origin policy/CORS principally govern response
access; browser simple-request rules, Fetch Metadata and private-network policies
can affect actual delivery. No permissive CORS policy will be introduced, and
protection must not rely on a particular browser blocking the request.

## Implementation Approach

1. Generate an unpredictable CSRF token for each application session. Serve it
   only through a guarded same-origin bootstrap. Require it for every private
   API read as well as action POSTs, protecting expensive diagnostic GETs too.
   Validate Host against explicit loopback literals and the actual bound port;
   validate supplied Origin and Fetch Metadata; reject foreign requests before
   parsing or dispatch. Bound and validate JSON request bodies, reject ambiguous
   framing, and add browser response protections without CORS exceptions.
2. Use one operation owner for disk/security/Installer review/manifest work.
   Perform final admission and registration atomically, reject admission after
   shutdown, retain ownership through cancellation/finalization, and guard stale
   publications by identity. Preserve existing scan-bound manifest checks.
3. Introduce a shared atomic JSON writer and serialize complete allowlist
   transactions, including processes sharing the storage directory. Validate
   before publication. Missing data and damaged existing data are different
   conditions: corruption must block modification and explain deliberate
   recovery. Apply atomic publication to closely related records/baselines.
4. Record selection and status for eight standard collectors, file verification
   and five advanced collectors. Distinguish `complete`, `disabled`,
   `unavailable`, `access_denied`, `partial`, `failed` and `cancelled`; retain
   pending/running states during execution. Derive summaries from this ledger,
   not finding counts or a legacy Boolean. Historical missing coverage is
   **not recorded**, never inferred complete, and old files are not rewritten.
5. Add deterministic tests using barriers/events, isolated storage and fake
   collectors. Keep the 28 existing regression behaviors. Establish Windows CI
   with Python/JavaScript/import/startup/API checks and failure on unexpected
   test skips. Run native/browser checks only within authorized boundaries;
   document unavailable checks as **NOT VERIFIED**.
6. Update maintained version/docs, perform adversarial self-review, repeat all
   applicable checks, commit and push this branch, then open an **unmerged** PR.

## Non-Goals and Constraints

No automatic deletion, quarantine, moves, patch application, registry backup,
service/Defender changes, deployment or merge. Installer confidence/coverage,
eligibility, nanosecond timestamp/size checks, SHA-256 snapshot validation and
stale-review rejection remain required. Local processes running as the same
user remain outside the browser-CSRF protection boundary. Atomic publication
does not claim filesystem-independent power-loss durability or protect data
against a malicious same-user process. Native permission and browser-policy
limitations must be reported, not bypassed.
