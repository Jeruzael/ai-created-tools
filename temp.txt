I based this redesign on your current dashboard context: the existing app is local-first, browser-based, light admin-dashboard style, uses compact tables/panels, and repeatedly explains that it is read-only, local-only, and does not make malware verdicts. 

Here’s a clean UI design draft you can use for Codex or your documentation.

# Windows Health & Security Review Dashboard UI Design Draft

* Document: Registry and Security Check UI Design
* App Context: Local Windows browser dashboard
* Status: Draft
* Goal: Add a simple, organized, text-heavy but readable security review interface
* Safety Position: Read-only review tool, not a malware verdict engine

---

## 1. Design Goal

The new UI should help users review Windows security-related areas in a calm, organized, and non-technical way.

The app should check registry entries, startup locations, scheduled tasks, browser policies, proxy/DNS settings, Defender exclusions, WMI persistence, event logs, optional Sysmon data, file signatures, SHA-256 hashes, suspicious command lines, baseline changes, suspicious names, and known-safe allowlists.

The UI must be detailed enough for technical users, but still understandable for non-technical users.

The main design rule:

> Show evidence clearly. Do not scare the user. Do not say something is malware unless verified by a real security engine. Use “review needed,” “suspicious pattern,” or “high-risk pattern” instead.

## 4. Top Safety Notice

Place this at the top of the Security Check tab.

Title:

```txt
Before You Run a Security Check
```

Message:

```txt
This tool reviews Windows settings, startup locations, registry keys, browser policies, scheduled tasks, and security-related indicators. It does not delete files, edit the registry, stop programs, quarantine files, or make final malware verdicts.

Findings mean “review this,” not “this is malware.”
```

Use a blue information alert with a left border.

Add a checkbox before running the scan:

```txt
I understand this is a review report and not a malware verdict.
```

Start button should be disabled until checked.

Danger-style actions should not appear here because the app should not clean or delete anything.



Example risk card:

```txt

Reason:
- Starts automatically
- Runs from AppData
```

Add explanation:

```txt
A higher score means the item has more suspicious patterns. It does not prove the file is malware.
```

## 11. Non-Technical Explanation Panel

Every finding should include a plain-language explanation.

Example:

```txt
What this means:
This setting tells Windows to start a program automatically when you sign in.

Why this needs review:
The program starts from your AppData folder and does not have a valid digital signature. Some legitimate apps do this, but unwanted software also commonly uses this method to stay active after reboot.

What you should do:
Do not delete it yet. First check the file name, publisher, signature status, SHA-256 hash, and whether you recently installed software related to it.
```

Use this format for every finding:

```txt
What this is
Why it matters
Why it was flagged
What to check next
What not to do
```

This makes the UI text-heavy but still easy to read.

## 28. Quarantine Recommendation Mode

Do not add automatic quarantine.

Instead, add:

```txt
Recommended Next Steps
```

For high-review items, show a safe checklist:

```txt
1. Do not delete this item yet.
2. Check the file signature and publisher.
3. Copy the SHA-256 hash for review.
4. Check whether you recently installed related software.
5. Run Microsoft Defender Full Scan or Offline Scan.
6. Disable only if you understand the effect.
7. Prefer uninstalling the related app from Windows Settings.
8. Keep the registry backup before making changes.
```

Use label:

```txt
Manual Review Guidance
```

Avoid button labels like:

```txt
Quarantine Now
Delete Threat
Remove Malware
Clean PC
```

Better button labels:

```txt
Copy Evidence
Open File Location
Copy SHA-256
Show Verification Steps
Show Safe Next Steps
```

## 37. Final Design Principle

The UI should feel like a calm investigation dashboard.

Not scary.
Not decorative.
Not too technical at first glance.
Not hiding details.

The best user experience is:

```txt
Simple summary first.
Clear findings second.
Evidence third.
Safe explanation fourth.
Technical details only when needed.
Manual next steps last.
```

The app should help users understand what changed, what needs review, why it was flagged, and what safe action they can take next.

My strongest recommendation: make **Security Check** one tab first, then use internal blocks/filters instead of adding too many new main tabs. That keeps the app simple even though the feature set is powerful.
